# PhilosophyOS RAG 检索方案实验

## 1. 结论

MVP 推荐采用“结构化过滤 + 混合排序 + 独立引用策略门”的组合：先按人物、传统、来源等级和发布状态过滤，再以向量相似度与关键词覆盖率排序。纯向量只保留为无实体识别结果时的低置信候选，不直接驱动引语。

## 2. 实验范围

- 固定小型语料：康德、斯宾诺莎、尼采、休谟各一个测试片段。
- 固定问题：4 个，其中一个故意让康德与斯宾诺莎的“自由”向量高度相似。
- 策略：纯向量、向量与关键词混合、结构化过滤后混合排序。
- 本地环境：Python 3.12，内存数据结构，每个固定问题重复 2,000 次；延迟仅用于比较算法开销，不代表 PostgreSQL、pgvector、网络或模型响应时间。
- 引用门：发布状态、证据类型、S1 等级、具体版本、版权状态、引用许可和逐字匹配。

## 3. 结果

| 方案 | Hit@1 | MRR | P95 本地检索延迟 | 主要失败 |
| --- | ---: | ---: | ---: | --- |
| 纯向量 | 75% | 87.5% | 0.049 ms | 康德/斯宾诺莎“自由”语义碰撞 |
| 混合检索 | 100% | 100% | 0.052 ms | 人物同名、元数据缺失时仍可能跨实体 |
| 结构化过滤 | 100% | 100% | 0.015 ms | 依赖实体识别和来源元数据质量 |

准确率来自固定回归集。结构化方案在本次小语料中更快，是因为硬过滤减少了待评分候选；该结果不能外推为生产数据库延迟。

## 4. 引用 blocker

以下情况全部禁止构造直接引语：

1. 片段尚未 published。
2. 片段没有被审核为 direct_quote 证据。
3. 来源不是 S1 原典。
4. 缺少具体版本。
5. 版权状态未完成审核。
6. 当前版本不允许展示引语。
7. 拟引用文字与检索片段不逐字匹配。
8. 引语为空。

检索得分不能覆盖任何 blocker；失败结果返回稳定原因码，供 API 降级为转述或“当前资料不足”。

## 5. 推荐参数与执行顺序

- 默认向量权重 `0.65`、关键词覆盖权重 `0.35`，后续在 200–500 个合法片段上重新调参。
- 已识别人物或著作时必须使用结构化过滤；没有可靠实体识别时允许混合检索，但结果标记为低置信候选。
- 只从 published 片段生成知识回答。
- 直接引语在检索后再次通过独立引用策略门，不复用排序分数作为许可依据。
- 页码和位置始终绑定 SourceChunk 的版本快照，不跨译本或版本复用。

## 6. 失败案例与修复策略

| 失败 | 原因 | 修复 |
| --- | --- | --- |
| 语义相似人物互相抢占 | 纯向量无法稳定表达作者约束 | 人物实体过滤 + 关键词排序 |
| 关键词正确但来源不可引用 | 召回质量与版权/审核状态是不同问题 | 独立引用 blocker |
| 结构化方案返回空 | 实体或来源元数据缺失 | 明确降级到低置信混合候选，不生成引语 |
| 版本不明却请求页码 | 页码无法跨版本复用 | 要求用户提供译本/版本 |
| 错误著作归属 | 查询前提中的作者与著作冲突 | 先检查 authored 关系，再进入内容检索 |

## 7. 正式知识库前的数据清洗要求

- 每个片段必须有稳定 source_id、chunk_id 和内容哈希。
- 人物、著作与概念关联必须来自审核数据，不按年代自动推断。
- 直接引语必须保存具体版本和逐字原文。
- 来源等级、版权状态、引用范围和发布状态不可为空。
- 删除或停用 Source 时同步移除其检索候选。
