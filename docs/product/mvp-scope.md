# PhilosophyOS MVP 范围说明

## 1. 目标

在 6–8 周内交付一个可真实使用的闭环：用户从自己的 Obsidian 开放问题或审核题库获得每日问题，与 AI 完成 2–5 轮思辨对话，查看可靠引用，确认总结，并把结果保存成符合现有习惯的 Markdown 笔记。

## 2. 核心用户

MVP 首先服务已经使用 Obsidian 记录哲学问题、愿意长期回顾个人观点的中文用户。首位验证用户是现有 `Stu的哲学思考` 仓库使用者。

## 3. 必须交付

| 能力 | 用户结果 | MVP 验收 |
| --- | --- | --- |
| Obsidian 只读索引 | 系统理解已有主题、链接和开放问题 | 能解析 YAML、章节、标签、任务和双向链接 |
| 每日问题 | 用户每天获得一个有依据的问题 | 问题展示来源、领域、难度和推荐原因 |
| 苏格拉底式对话 | 用户通过追问澄清观点 | 连续 2–5 轮，每轮只问一个核心问题 |
| 可信 RAG | 用户能核对知识性陈述 | 断言有来源；证据不足时明确拒绝确定性回答 |
| 观点归属 | 他人观点不会被写成用户立场 | 区分用户、第三方、作者和 AI 四种主体 |
| Markdown 草稿 | 思考进入长期知识仓库 | 生成 YAML、固定章节和关联链接，确认后写入 |
| 思想回顾 | 用户能看到同主题历史回答 | 展示原文对比，变化结论由用户确认 |

## 4. 内容范围

### 4.1 MVP 范围

- 仅覆盖西方哲学。
- 时间从前苏格拉底哲学至当代哲学。
- 首批种子哲学家全部达到 L1，重点人物达到 L2/L3。
- 首批问题覆盖认识论、伦理学、自由意志、形而上学、存在主义、政治哲学和科学哲学。

### 4.2 后期范围

中国哲学在 Phase 4 加入，使用独立时代轴、经典谱系和概念分类。中西比较只有在双方内容和评测成熟后开放。

好友关系和私密哲学讨论作为核心单人闭环后的 P1 阶段交付。该阶段必须同时提供好友请求、讨论邀请、服务端房间权限、拉黑举报和独立个人总结，不允许只上线“添加好友”和聊天入口。

### 4.3 不进入 MVP

- Neo4j 复杂图谱界面。
- 哲学家多 Agent 自动辩论。
- OCR、拍书页和手写识别。
- 社区、排行榜和公开用户画像。
- 自动改写 Obsidian 核心笔记。
- 中国哲学及其他非西方哲学公共知识库。
- 好友、多人讨论和社交通知；这些功能不阻塞最初的单人 MVP 发布。

## 5. 演示路径

1. 连接测试 Obsidian 仓库。
2. 系统从“继续追问”提取一个自由意志问题。
3. 用户提交初步观点。
4. AI 先区分行动自由、能动性和形而上自由，再进行追问。
5. 用户请求查看斯宾诺莎与相容论的相关观点。
6. 系统返回带来源回答，明确原典、研究解释和 AI 综合。
7. 对话结束后生成观点卡片和 Markdown 草稿。
8. 用户修改“暂定立场”，确认写入测试仓库。
9. 系统刷新开放问题和关联链接。

当前本地 Beta 的主导航只保留已完成模块，不把好友、笔记工作台、云同步和计费放进主路径；这些能力保留在后续计划中。

## 6. 成功指标

- 首题完成率不低于 50%。
- 已开始挑战的总结完成率不低于 60%。
- 知识性回答引用覆盖率不低于 90%。
- 他人观点误记为用户观点的阻断级错误为 0。
- 未确认写入 Obsidian 的阻断级错误为 0。
- 首批评测集中，引用真实性和观点归属测试通过率均不低于 95%。

## 7. 发布阻断条件

出现下列任一问题时不得发布：

- 模型生成不存在的直接引语、页码或著作。
- 未经确认创建、覆盖、删除或重命名 Obsidian 文件。
- 将第三方观点写入用户的“我的暂定立场”。
- 无法删除长期记忆或撤销最近一次 AI 写入。
- 把中国哲学概念强制套入西方哲学分类后对外展示。

## 8. 商业化前必须补齐的隔离边界

本地 Beta 可以把数据视为“单用户、单工作区”。商业化版本不能继续沿用这个假设。所有后续账号、同步、计费和团队功能都必须围绕 `user_id` 与 `workspace_id` 展开。

### 8.1 最小产品边界

- 每个用户至少拥有一个默认工作区。
- 所有对话、思想快照、开放问题、周报、Obsidian 草稿、写入审计和模型配置都属于某个工作区。
- 哲学家图鉴、公共哲学概念、公共来源和种子问题属于公共数据，不归某个用户所有。
- 用户对公共哲学家的筛选、收藏、关联证据属于用户工作区。

### 8.2 数据导出范围

用户导出自己的工作区时，应包含：

- 对话原文、AI 回复、模型名称和时间；
- 思想快照、用户确认/修改/拒绝记录；
- 开放问题、思想张力、哲学家影响证据；
- 周报草稿和用户确认后的报告；
- Obsidian 草稿、确认写入记录和撤销记录；
- 非敏感设置，例如模型名称、Base URL、API 风格。

导出必须排除：

- 完整 API Key；
- 加密后的 Key envelope；
- 其他用户或其他工作区数据；
- 系统运维日志、计费内部字段和客服私有备注。

### 8.3 删除范围

普通删除：

- 删除单条思想快照时，只删除该快照和从它派生的图谱/聚合视图。
- 删除对话时，需要提示是否保留已确认的思想快照。
- 删除 Obsidian 写入记录不能直接删除用户本地文件；只能提供“撤销最近一次 AI 写入”或清理审计记录。

工作区删除：

- 仅 owner 可执行。
- 删除前展示对象数量、时间范围、是否包含模型配置和导出包。
- API Key 必须立即移除或密钥粉碎。
- 公共哲学数据不能被工作区删除影响。

### 8.4 权限与角色

商业化第一版建议只开放：

| 角色 | 能力 |
| --- | --- |
| owner | 账单、工作区删除、全量导出、成员管理 |
| editor | 日常对话、快照、报告、Obsidian 草稿 |
| viewer | 查看档案、图谱、报告，不可写入 |

即使短期内还没有团队功能，也要在数据模型中预留这些字段，避免后面把个人数据和团队数据缠在一起。

## 9. 账户与同步产品边界

### 9.1 普通用户路径

普通用户打开应用即可使用本地模式，不需要注册账号，也不需要填写 API Key。应用使用默认本地工作区保存对话、思想快照、关系图谱状态和 Obsidian 配置。

产品界面应把“登录同步”作为可选升级入口，而不是首次使用门槛：

- 未登录：显示“本地模式”，明确提示数据保存在本机；
- 已登录但未选择云工作区：继续使用本地模式；
- 已登录并选择云工作区：显示同步状态、最近同步时间和冲突提示；
- 团队工作区：额外显示成员角色和共享范围。

### 9.2 本地模式与云同步模式的差异

| 能力 | 本地模式 | 云同步模式 |
| --- | --- | --- |
| 无账号使用 | 支持 | 不适用 |
| 对话、快照、关系图谱 | 本机保存 | 本地缓存并同步 |
| Obsidian | 直接访问用户目录 | 仍由用户设备访问，云端只保存索引/草稿元数据 |
| API Key | 本机加密保存 | 不上传；未来托管密钥单独处理 |
| 多设备 | 不同步 | 同一用户可同步 |
| 数据删除 | 本机删除/撤销 | 按工作区权限和审计流程删除 |

### 9.3 登录和迁移体验

登录后不自动上传历史数据。首次绑定云工作区时，提供三个明确选项：

1. **上传本地数据**：将选定的本地对象复制到云工作区；
2. **下载云端数据**：将云端对象复制到本地缓存；
3. **保持分开**：保留两个工作区，用户之后再决定。

迁移前展示对象数量、时间范围、目标工作区和预计冲突数量。迁移完成后给出可下载的迁移报告；失败时可重试，不影响原始数据。

### 9.4 MVP 不做的账户能力

本阶段不实现完整 OAuth、计费、团队邀请、跨设备实时协作或云端 API Key 托管。当前只需确保：

- 本地模式不被登录流程阻塞；
- 后端模型可区分用户和工作区；
- 文档、UI 文案和未来 API 都不把本地数据误认为云端数据；
- 后续新增同步接口时，所有私有对象都能按 `workspace_id` 隔离。
