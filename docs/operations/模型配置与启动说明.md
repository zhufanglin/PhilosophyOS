# PhilosophyOS 模型配置与启动说明

这份文档用于本地启动 PhilosophyOS，并维护“免费 / GPT / DeepSeek”三套模型配置。它只记录占位示例，不要在文档、README、前端代码或测试文件里写真实 API Key。

## 快速启动

在项目根目录运行：

```powershell
cd C:\Users\30290\Desktop\PhilosophyOS
.\scripts\start-dev.cmd
```

启动后访问：

```text
http://127.0.0.1:5174/#today
```

一键启动脚本会启动两个服务：

| 服务 | 默认地址 | 用途 |
| --- | --- | --- |
| 前端 Web | `http://127.0.0.1:5174/#today` | 浏览器页面 |
| 后端 API | `http://127.0.0.1:8001` | FastAPI 本地服务 |

如果使用脚本启动，请保持两个 PowerShell 窗口打开。关闭窗口会停止对应服务。电脑关机或重启后，也需要重新运行启动脚本。

## 常见地址

- 前端页面：`http://127.0.0.1:5174/#today`
- 后端健康检查：`http://127.0.0.1:8001/health`
- 模型状态接口：`http://127.0.0.1:8001/api/v1/model-profiles`

如果浏览器打开了 `http://127.0.0.1:8001/`，看到的不是前端页面；那是后端服务地址。前端页面应打开 `5174`。

## `.env` 放在哪里

本地真实密钥放在：

```text
apps/api/.env
```

这个文件已被 `.gitignore` 忽略，不应提交到 GitHub。

可以从项目根目录的 `.env.example` 复制配置项，再填入自己的值。只复制变量名和占位结构，不要把真实 key 写进示例文件。

## 三套模型配置

后端支持三个 profile：

| profile | 前端名称 | 用途 |
| --- | --- | --- |
| `free` | 免费 | 默认免费额度模型，目前建议豆包/火山方舟 |
| `gpt` | GPT | OpenAI 官方或 OpenAI-compatible 中转站 |
| `deepseek` | DeepSeek | DeepSeek 官方兼容接口 |

前端只发送 `model_profile`，不会接触 API Key。API Key 只由后端读取。

## 推荐 `.env` 模板

```env
PHILOSOPHYOS_MODEL_PROFILE=free
PHILOSOPHYOS_AI_PROVIDER=auto

FREE_API_KEY=<填入免费模型平台的 key>
FREE_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
FREE_MODEL=doubao-seed-2-0-lite-260428
FREE_API_STYLE=responses

GPT_API_KEY=<填入 GPT 或 GPT 中转站 key>
GPT_BASE_URL=https://api.synapai.top/v1
GPT_MODEL=gpt-5.6
GPT_API_STYLE=responses

DEEPSEEK_API_KEY=<填入 DeepSeek key>
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-v4-flash
DEEPSEEK_API_STYLE=chat_completions
```

如果只想临时默认使用某一个模型，改：

```env
PHILOSOPHYOS_MODEL_PROFILE=free
```

可选值：

- `free`
- `gpt`
- `deepseek`

## DeepSeek 模型选择

DeepSeek 默认 Base URL：

```text
https://api.deepseek.com
```

当前只建议保留两个模型选项：

- `deepseek-v4-flash`：默认选项，适合速度和成本优先。
- `deepseek-v4-pro`：适合更复杂的哲学推理。

DeepSeek 使用：

```env
DEEPSEEK_API_STYLE=chat_completions
```

## GPT 或中转站配置

如果使用 OpenAI-compatible 中转站，通常需要：

```env
GPT_API_KEY=<中转站提供的 key>
GPT_BASE_URL=https://你的中转站地址/v1
GPT_MODEL=<中转站支持的模型名>
GPT_API_STYLE=responses
```

如果中转站不是 Responses 风格，而是 Chat Completions 风格，将：

```env
GPT_API_STYLE=chat_completions
```

## 免费模型配置

免费模型目前建议使用豆包/火山方舟免费额度：

```env
FREE_API_KEY=<填入火山方舟 key>
FREE_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
FREE_MODEL=doubao-seed-2-0-lite-260428
FREE_API_STYLE=responses
```

以后如果换成通义、OpenRouter Free 或其他免费模型，只需要替换 `FREE_*` 这一组，不影响 GPT 和 DeepSeek。

## 前端模型设置面板怎么用

在页面顶部点击“设置”，会打开“模型设置”面板。

面板里可以看到：

- 当前使用哪个模型。
- 三套模型是否已配置。
- 每套模型的模型名。
- 每套模型的服务 host。
- 每套模型的接口类型。
- 每套模型的连接测试按钮。

点击“测试连接”后，后端会发起一次极短测试请求。测试结果只显示安全状态，不显示 API Key。

## 对话时的模型兜底

对话页面会显示当前模型的思考状态，例如：

```text
DeepSeek 正在思考中
```

如果当前模型失败，系统会保留你的回答，不重复记录用户发言。非免费模型失败时，可以点击：

```text
切换到免费模型并重试
```

它会自动把当前模型切到 `free`，并重新请求哲学引导。

## Obsidian 草稿输出目录

对话结束后，确认页面可以生成 Obsidian Markdown 草稿。默认输出目录是：

```text
D:\Obsidian\storage\Stu的哲学思考\PhilosophyOS\草稿
```

如需修改，在 `apps/api/.env` 中设置：

```env
OBSIDIAN_DRAFTS_DIR=D:\Obsidian\storage\Stu的哲学思考\PhilosophyOS\草稿
```

前端不会传入任意文件路径。后端只读取这个固定配置，并自动创建目录、生成不覆盖旧文件的 `.md` 草稿。

## 常见问题

### 前端打不开

先确认打开的是：

```text
http://127.0.0.1:5174/#today
```

如果仍打不开，重新启动：

```powershell
cd C:\Users\30290\Desktop\PhilosophyOS
.\scripts\start-dev.cmd
```

### 后端打不开

检查：

```text
http://127.0.0.1:8001/health
```

正常时会返回：

```json
{"status":"ok","service":"philosophyos-api","version":"0.1.0"}
```

### 关闭终端后页面失效

这是正常现象。当前是本地开发模式，前端和后端依赖终端进程。关闭窗口、电脑关机或重启后，需要重新运行启动脚本。

### 模型显示未配置

检查 `apps/api/.env` 中对应 key 是否存在、是否没有被 `#` 注释：

```env
FREE_API_KEY=
GPT_API_KEY=
DEEPSEEK_API_KEY=
```

不要在终端或聊天里打印真实 key。只检查“是否填写”和“是否被注释”即可。

### 模型测试失败

优先检查：

1. API Key 是否正确。
2. Base URL 是否带了正确路径，例如 GPT 中转站常见是 `/v1`。
3. 模型名是否被服务商支持。
4. API 风格是否匹配：`responses` 或 `chat_completions`。
5. 当前服务商是否限流或余额不足。

### 为什么不能把 API Key 放到前端

浏览器里的代码会被用户看到。只要把 key 写进前端，任何打开页面的人都可能拿到它。

正确做法是：

- 前端只选择 `free / gpt / deepseek`。
- 后端读取 `.env` 中的密钥。
- 后端代替前端调用模型。
- 返回给前端的只有回答和安全状态。
